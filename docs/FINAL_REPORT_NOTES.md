## Application and identity construction

The square stores signed integer heights. Active cells form a disk intersected with `j <= max(i,N-1-i)`, using the exact inclusive integer circle predicate centered at `N/2` with radius `N/2`. At N=1001, 589,365 of 1,002,001 cells are active, producing a radius-500 Pac-Man shape. Odd/even behavior follows the original expression. An active height >=4 topples, losing four grains and adding one to each in-bounds orthogonal neighbor. Excluded in-square cells retain grains but never topple; grains crossing the square disappear.

Identity computation fills every stored cell with six, stabilizes, complements every height as `6-height`, and stabilizes again. Both stages repeatedly relax the active graph. The original recomputes geometry and performs only one toppling per unstable visit, so cost is proportional to active/prefix visits across many data-dependent sweeps. Inactive counters can become negative after complementation. Since many integers render as black, image equality alone is insufficient.

## Profiling-to-optimization argument

Baseline N=251 diagnostics: 10,965 sweeps; 519,477,840 prefix visits; 404,564,640 active visits; 179,766,102 legal unit topplings. Inactive cells account for 22.12% of prefix visits, and stable cells for 55.57% of active visits. At unstable visits, 35.10% had quotient height/4 equal to two. Separate N=251 gprof source attribution assigned approximately 27.5% to geometry and 23.7% to loop lines. N=101 Callgrind assigned 98.86% of original instructions to stabilization. These are exploratory smaller workloads, not target-size CPU-time fractions.

| Change | Motivation and implementation | Correctness / decision |
|---|---|---|
| Row intervals | Remove repeated geometry and inactive scans; precompute exact first/last columns per row | Same active visit order and writes; retained |
| Batched topplings | Replace q consecutive legal topplings by subtracting 4q and adding q to neighbors | h>=4q, so every bundled toppling is legal; checked implementation slowed down |
| Once-per-stage bound | Per-neighbor overflow checks inflated instruction count; select unchecked kernel when initial sum of positive heights <=INT_MAX | Legal topplings cannot increase that sum; negative sinks only increase; checked fallback retained |
| FIFO unit / batch | Avoid the 55.57% stable visits using a bounded circular queue and duplicate flags | Correct smaller cases, but four-recipient scheduling/membership costs dominate; rejected |
| Contiguous storage | Test locality/allocation hypothesis without changing indexed access | Shared production/test allocation; no larger-size gain; rejected |
| Alternating sweeps | Reverse complete passes to reduce directional propagation delay without per-cell scheduling | Legal full passes, unique stable state/odometer; independently target-verified |
| Padded boundaries | Remove neighbor conditions in safe kernel with a one-cell absorbing halo | Halo never feeds back and is cleared each phase; checked fallback keeps physical guards; independently target-verified |
| Explicit remainder mask | State h mod 4 directly for positive h | Correct, but GCC generated byte-identical machine-code text; rejected |

The final combination is measured directly; individual gains are not multiplied. N=251 bounded batching uses 9,007 sweeps, 332,322,272 visits and 151,609,190 batched events. Alternating sweeps, including the padded combination, use 8,707 sweeps and 321,253,472 visits; all retain 179,766,102 unit topplings. Padding alone leaves those work counts unchanged. The larger combined improvement includes interaction between loop ordering and generated code; the data do not isolate a hardware cache or branch-prediction cause.

See [detailed proofs and methods](FINAL_METHODS.md) and [independent extension experiments](ADDITIONAL_EXPERIMENTS.md). The Abelian finite dissipative graph has a unique stable state and odometer under legal topplings, preserving physical sink increments despite changed order. Padding retains physical indices and uses production allocation in the test adapter. The positive-grain proof covers the initially zero halo; the fallback avoids writing outside physical boundaries.

## Introspection and three-page paper priorities

Row intervals were the largest individual improvement. Batching initially disappointed despite fewer visits; checking every addition erased its work reduction. A once-per-stage proof made batching profitable. FIFO avoided stable scans but replaced cheap streaming checks with expensive queue/membership operations. Contiguous allocation alone did not improve the larger workloads, and the remainder rewrite duplicated an optimization GCC already performed. Alternating sweeps and padding address different costs; their combination must be evaluated directly because compiled-loop interactions make gains nonmultiplicative.

For a three-page SIGPLAN paper, explain the mask/two-stage computation first, then connect each retained change to the measured bottleneck and correctness invariant. Use the compact target table and two vector figures, report dispersion and n explicitly, and summarize rejected ideas in a short paragraph. Keep full raw tables, all command lines, proofs and negative variants in this artifact. This directly addresses the HW2 requests for clearer background, profiling motivation, stronger correctness, timing dispersion and reproducibility.
